# Radko Farm — сайт аптеки

Готовый статический сайт для GitHub Pages с русским, английским и египетским арабским интерфейсом. Включает каталог, поиск и фильтры, корзину, предварительный расчёт доставки, заявку через WhatsApp, профиль владельца, ссылку и встроенный поиск на Google Maps. Панель `admin.html` позволяет владельцу добавлять товары и фотографии через браузер. Данные хранятся в Supabase.

## Что уже работает и что потребуется настроить

- Главная, три языка, адаптивная вёрстка, анимации, телефоны, WhatsApp и ссылка на указанную точку Google Maps работают сразу.
- Список товаров пуст до подключения Supabase и добавления настоящих позиций. Выдуманных лекарств, цен и наличия нет.
- Корзина сохраняется в браузере покупателя. При отправке открывается WhatsApp с готовым сообщением, которое **покупатель сам отправляет**. Это заявка, а не онлайн оплата или автоматически зарегистрированный заказ.
- `near: 30` и `far: 60` в `config.js` — **примерные ставки EGP**. Замените на реальные значения или поставьте `0`. Это выбор зоны, а не вычисление расстояния по дорогам. Аптека подтверждает сумму.
- Кнопка Telegram появляется только после настройки **своего проверенного** `telegramUsername` в `config.js`. Браузер скопирует заказ и откроет чат; покупатель вставит и отправит сообщение. Telegram не гарантирует предзаполнение сообщения для обычного чата.
- Встроенная карта использует поиск по названию. **Точный пин** открывается по предоставленной вами ссылке. Если Google показывает другое место во встроенной карте, замените `iframe` в `index.html` на код «Поделиться → Встроить карту» с карточки своей аптеки. Для Maps Embed API с собственным ключом нужен отдельный проект и настройка Google Maps Platform.

## Быстрый просмотр на компьютере

Сложите файлы в одной папке, затем запустите локальный сервер:

```bash
python -m http.server 8000
```

Откройте `http://localhost:8000/`. Можно открыть `index.html` напрямую, но для проверки подключения и навигации удобнее сервер. При отсутствии настроенного Supabase каталог покажет понятное пустое состояние.

## Шаг 1. Создайте Supabase для загрузки товаров и фото

1. Зарегистрируйтесь на [supabase.com](https://supabase.com/) и создайте проект. Запишите пароль БД в надёжном месте.
2. Откройте **SQL Editor → New query**. Скопируйте весь `supabase.sql`, нажмите **Run**. Он создаёт таблицы, правила доступа и публичное хранилище `images` с загрузкой **только** для владельца.
3. В **Authentication → Users → Add user** создайте **свой** email и пароль. Если интерфейс предлагает подтверждение email, подтвердите его или настройте аккаунт согласно подсказке Supabase. Откройте созданного пользователя и скопируйте его **User UID**.
4. В SQL Editor выполните **отдельно** команду ниже, заменив пример UUID на ваш User UID:

   ```sql
   insert into public.admin_users (id)
   values ('xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx');
   ```

   Не размещайте настоящий UID как пароль. Эта таблица даёт право редактирования только указанному аккаунту, а проверка проводится правилами базы данных.
5. В **Project Settings → API Keys** возьмите **publishable** (или legacy **anon**) key. В **Project Settings → Data API** найдите **Project URL**. Вставьте их в `config.js`:

   ```js
   supabaseUrl: 'https://ВАШ-ПРОЕКТ.supabase.co',
   supabaseAnonKey: 'ВАШ_PUBLISHABLE_ИЛИ_ANON_KEY',
   ```

   Публичный ключ допустим на сайте. **Никогда не добавляйте `service_role`, `secret` key, пароль или токен GitHub в файлы сайта.** Ограничение доступа обеспечивают RLS политики из `supabase.sql`.
6. Откройте `admin.html`, войдите своим email и паролем. Добавьте первый товар и фотографию. Откройте главную страницу заново: товар должен появиться. Загрузите фото владельца в разделе «Владелец аптеки».

### Как добавлять товары после публикации

Откройте `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/admin.html`, введите email и пароль, заполните три названия и при необходимости три описания, категорию, цену, наличие и фото, нажмите **«Сохранить товар»**. Чтобы изменить товар, нажмите **«Изменить»** в списке. Для фото владельца заполните имена и выберите файл в нижнем блоке. JPG/PNG/WebP до 3 МБ. Изменения в Supabase сразу видны посетителям при следующем открытии страницы; GitHub повторно загружать не нужно. Панель доступна по ссылке всем, но операции записи допускаются только аккаунту из `admin_users`.

## Шаг 2. Загрузите сайт на GitHub Pages

1. Распакуйте ZIP. Создайте на [github.com/new](https://github.com/new) **публичный** репозиторий, например `radko-farm`. Можно выбрать `Add a README` = off, чтобы не создавать конфликтов.
2. В репозитории нажмите **Add file → Upload files**. Перетащите **содержимое** папки `radko-farm` в корень репозитория: `index.html`, `admin.html`, `app.js`, `admin.js`, `styles.css`, `config.js`, `supabase.sql`, `README.md` и папку `assets`. Убедитесь, что `index.html` в корне, а не внутри дополнительной вложенной папки. Нажмите **Commit changes**.
3. Откройте **Settings → Pages → Build and deployment**. Выберите **Deploy from a branch**, ветку **main**, папку **/(root)**, сохраните.
4. GitHub покажет ссылку в разделе **Pages**. Обычно это `https://ВАШ-ЛОГИН.github.io/radko-farm/`. Дождитесь публикации (часто несколько минут), откройте ссылку и проверьте карточку товара, языки и корзину.
5. Изменения кода (`config.js`, оформление, телефоны) в будущем потребуют нового коммита. Изменения товаров и портрета через `admin.html` — нет.

С телефона: зайдите на github.com в браузере, при необходимости включите «Версия для ПК», распакуйте архив в «Файлы» и загрузите файлы через **Add file → Upload files**. Для большого числа файлов удобнее GitHub Desktop на компьютере.

## Контакты, карта и стоимость доставки

Откройте `config.js`. `primaryWhatsApp` — номер без `+`, он используется в заявках. `secondaryPhone` показан как дополнительный номер в HTML. Если телефон меняется, обновите также ссылки `tel:` и ссылку `wa.me` в `index.html`. `mapsUrl` уже содержит вашу точную ссылку `https://maps.app.goo.gl/P6s7EeJ9SLahWybB9?g_st=atm`. Параметр `g_st=atm` — служебная часть ссылки, для пользователя менять его не требуется.

В `deliveryFees` задайте реальные **предварительные** цены для `pickup`, `near`, `far`; если зона определяется иначе, поменяйте подписи во всех трёх словарях `app.js`. Без адреса и подтверждённых тарифов точный расчёт по километрам не включён.

## Безопасность и ограничения

- Не загружайте фотографии рецептов или личные медицинские данные покупателей через каталог. Заявки уходят в мессенджер по действию клиента и **не сохраняются** в базе сайта.
- Публикуйте лекарственные товары и рекламные заявления только после проверки местных правил и лицензии аптеки. Текст сайта не даёт диагнозов или схем лечения. Наличие и отпуск рецептурных препаратов подтверждает сотрудник аптеки.
- На бесплатном тарифе Supabase есть лимиты и проект может останавливаться после периода неактивности. Следите за использованием и делайте резервную копию товаров. Изображения, которые заменены или относятся к удалённым товарам, можно очистить в **Storage → images**.
- Публичное хранилище означает, что изображения доступны по URL всем; фотографии владельца размещайте только с его согласия.
- Включайте HTTPS (GitHub Pages использует HTTPS), сильный пароль владельца и двухфакторную защиту аккаунтов GitHub/Supabase. Не выключайте RLS.

## Файлы

| Файл | Назначение |
| --- | --- |
| `index.html`, `styles.css`, `app.js` | Витрина, оформление и логика |
| `admin.html`, `admin.js` | Вход и редактирование через сайт |
| `config.js` | Публичная настройка телефонов, доставки и Supabase |

Сайт не требует сборки, Node.js и платного хостинга. CDN Supabase загружается только после заполнения `config.js`.
